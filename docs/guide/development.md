# Development

## The repository

| Path | Content |
|---|---|
| `src/index.js` | The package root: it exports the public API of every module. |
| `src/bosdyn-client/` | The clients and the helpers (the `bosdyn.client` package of Python), with `spot_cam/` and `gps/`. |
| `src/bosdyn-core/` | Utilities, geometry, text and JSON formats, `bddf/` (the `bosdyn` package of `bosdyn-core`). |
| `src/bosdyn-mission/`, `src/bosdyn-choreography-client/`, `src/bosdyn-orbit/` | Missions, choreography, Orbit. |
| `src/bosdyn/` | The protobuf messages and the gRPC clients, generated by `build.js`: do not edit them. |
| `typings/` | The typings, generated from the JSDoc by `npm run build:typings`. |
| `test/` | The tests (`node:test`), with the tests ported from the Python SDK. |
| `examples/` | The examples, each one with its `package.json`. |
| `docs/` | This documentation ([docsify](https://docsify.js.org/)); `docs/api/` is generated. |

## Scripts

| Script | Use |
|---|---|
| `npm test` | Runs all the tests (`test/test_*.js`) with `node --test`. `npm test -- --test-name-pattern=Lease` runs some of them. |
| `npm run lint` | ESLint and Prettier on the whole repository; `npm run lint:fix` fixes what can be. |
| `npm run build:typings` | Generates `typings/` from the JSDoc of `src/`. |
| `npm run test:typings` | Compiles `test/typings/usage.ts` in strict mode against the typings. |
| `npm run build:docs` | Generates the typings, then the API reference (`docs/api/`) and `docs/changelog.md`. |
| `npm run docs` | Serves the documentation on `http://localhost:3000`. |
| `npm publish` | Runs the lint, the typings check and the tests first (`prepublishOnly`), then publishes `src/` and `typings/`. |
| `npm run build` | Generates `src/bosdyn/` from the `.proto` files of the Spot SDK (`../spot-sdk-py/spot-sdk-5.2.0/protos`), with `grpc-tools`. |

The CI runs the lint and the tests on Node.js 24, checks that `typings/` is up to date, and analyzes the code with
CodeQL.

## Conventions

- **Follow the Python SDK.** Each module is the port of its Python counterpart, function by function; a deliberate
  difference is explained in the JSDoc of the function. The tests compare the behavior with Python when they can.
- **Document with JSDoc.** Every module starts with a `@file` comment, and every public class, function and method
  has a description and typed parameters: the typings and the API reference come from them.
- **Export from the root.** A new public name must be exported by `src/index.js`, or by the namespace of its package;
  `test/test_index.js` checks it. The names that several modules export with different values are listed there.
- **Style.** Prettier (`.prettierrc.json`) and ESLint (`eslint.config.cjs`), LF line endings, lines of 120 characters.
- **Regenerate** the typings after a change of the JSDoc or of the API (`npm run build:typings`), and the reference of
  the documentation (`npm run build:docs`).

## Testing without a robot

The tests start their gRPC servers on `127.0.0.1`, on free ports. To run an application against a mock robot, trust
its certificate authority with `BOSDYN_CA_CERT` (see [Installation](/guide/installation#certificate-of-the-robot)).

[spot-server-js](https://github.com/TheoPierne/spot-server-js) is a simulated Spot: the services of the API, backed
by a simulation which follows the rules of a robot (leases, E-Stop, time sync, power, faults, docking...), so the
examples and the applications run against it, and their errors are the ones of a real robot.

```bash
cd spot-server-js
npm start -- --host 127.0.0.1
```

```bash
BOSDYN_CA_CERT=../spot-server-js/src/resources/ca.crt node examples/hello_spot/hello_spot.js 127.0.0.1
```

- On another port than 443, call `robot.updateSecureChannelPort(port)` after `sdk.createRobot()`.
- Like a robot, it is E-Stopped until an E-Stop endpoint checks in: run the `estop` example next to the applications
  which power the robot on.
- Its console acts on the robot like the real world: press the hardware E-Stop, make the robot fall, drain the
  battery, raise faults, reboot the robot... `--clock-skew` shifts its clock, to check the time conversions.

## The documentation

The guides are the Markdown files of `docs/guide/`; the API reference (`docs/api/`) and `docs/changelog.md` are
generated by `build_docs.js` from the typings and their JSDoc, with the descriptions of the modules (`@file`) and of
their exports. The sidebar (`docs/_sidebar.md`) lists the guides; its entries after "API reference" are written by the
generator. Preview the site with `npm run docs`.
