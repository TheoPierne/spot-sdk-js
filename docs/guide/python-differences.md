# Differences with Python

spot-sdk-js follows the Python SDK 5.2.0: same modules, same classes, same behavior. A program of the Python SDK
translates line by line, with the rules of this page. The deliberate differences of a function are described in its
JSDoc, and in the [changelog](/changelog).

## Names and imports

| Python | JavaScript |
|---|---|
| `from bosdyn.client.robot_state import RobotStateClient` | `const { RobotStateClient } = require('spot-sdk-js');` |
| `get_robot_state()`, `blocking_stand()` | `getRobotState()`, `blockingStand()` (camelCase) |
| `RobotStateClient.default_service_name` | `RobotStateClient.defaultServiceName` |
| `bosdyn.client.exceptions.Error` | `BosdynError` (`Error` is the base class of JavaScript) |
| `bosdyn.client.spot_cam.ptz.PtzClient` | `spotCam.PtzClient` (or `spotCam.ptz.PtzClient`) |
| `bosdyn.api.robot_state_pb2` | `require('spot-sdk-js/src/bosdyn/api/robot_state_pb')` |
| `google.protobuf.text_format.Parse()`, `json_format.MessageToJson()` | `textFormat.parse()`, `jsonFormat.messageToJson()` |
| `None` | `null` |

The names that several modules export with different values (e.g. `NoTimeSyncError`) are required from their module:
see [Concepts](/guide/concepts#imports).

## Asynchronous calls

Every call to the robot returns a promise: the blocking calls of Python are `await`ed, and the `_async` variants of
Python (which return futures) do not exist, since every method is asynchronous.

```python
state = robot_state_client.get_robot_state()
```

```js
const state = await robotStateClient.getRobotState();
```

The background threads of Python (time sync, token refresh, keep-alives) are tasks on the event loop of Node.js. Like
the daemon threads of Python, the time sync and the token refresh do not keep the process alive; the keep-alives run
until their `shutdown()`.

## Context managers

The `with` blocks become `try`/`finally` blocks, or `await using` where the runtime supports it:

```python
with LeaseKeepAlive(lease_client, must_acquire=True, return_at_exit=True):
    ...
```

```js
const keepAlive = new LeaseKeepAlive(leaseClient, { mustAcquire: true, returnAtExit: true });
try {
  // ...
} finally {
  await keepAlive.shutdown();
}
```

The helpers that are context managers in Python (`AudioVisualHelper`, `LightsHelper`) have explicit `start()` and
`exit()` or `stop()` methods.

## Arguments

- The positional arguments keep the order of Python.
- The keyword arguments of the functions with many optional arguments are an **options object**:
  `synchro_stand_command(body_height=0.1)` is `synchroStandCommand({ bodyHeight: 0.1 })`, and
  `LeaseKeepAlive(client, must_acquire=True)` is `new LeaseKeepAlive(client, { mustAcquire: true })`. An unknown
  option throws a `TypeError`, like an unknown keyword argument.
- The `**kwargs` of the methods of the clients (`timeout=`...) are the last argument, `args`:
  `get_robot_state(timeout=5)` is `getRobotState({ timeout: 5_000 })`.

## Units

| Python | JavaScript |
|---|---|
| `timeout` of the RPCs, in seconds | `timeout` of the RPC options, in **milliseconds** (`null` for no deadline, like `None`) |
| `timeout_sec` of the blocking helpers, in seconds | `timeoutMsec`, in **milliseconds**: `blockingStand(client, 10_000)` |
| Parameters named `..._secs`, `..._seconds` | `...Secs`, `...Seconds`: seconds, like Python |

The name of a parameter tells its unit: `Msec` or `Ms` for milliseconds, `Sec`, `Secs` or `Seconds` for seconds.

## Protobuf messages

The messages are generated by [google-protobuf](https://github.com/protocolbuffers/protobuf-javascript): their fields
are accessed with methods.

| Python | JavaScript |
|---|---|
| `state.power_state.motor_power_state` | `state.getPowerState().getMotorPowerState()` |
| `msg.field = 1` | `msg.setField(1)` (the setters return the message: they chain) |
| `geometry_pb2.Vec3(x=1, y=2, z=3)` | `new geometryPb.Vec3().setX(1).setY(2).setZ(3)` |
| `msg.HasField('field')` | `msg.hasField()` |
| `msg.WhichOneof('command')` | `msg.getCommandCase()` (a number of the `CommandCase` enum) |
| `msg.items.append(item)`, `msg.items.extend(items)` | `msg.addItems(item)`, `msg.setItemsList([...items])` |
| `msg.map_field['key']` | `msg.getMapFieldMap().get('key')` |
| `msg.CopyFrom(other)` | `jspb.Message.copyInto(other, msg)`, or `other.clone()` |
| `msg.SerializeToString()`, `Msg.FromString(data)` | `msg.serializeBinary()`, `Msg.deserializeBinary(data)` |
| enums: `RobotState.X` | numbers on the message: `robotStatePb.PowerState.MotorPowerState.MOTOR_POWER_STATE_ON` |
| 64-bit integers | numbers (exact up to 2^53); strings for the BDDF hashes and additional indexes, the E-Stop challenges, the keepalive policy ids, the signal schema ids and the recording session ids |
| `bytes` | `Uint8Array` (`getData_asU8()`, `getData_asB64()`) |

## Other differences

- **Logging**: the SDK logs with winston instead of the `logging` module; `LoggerUtil.getLogger(name)` returns a
  logger, and `setupLogging()` works like the Python helper.
- **Math**: the matrices of the math helpers are `NdArray`s of [numjs](https://www.npmjs.com/package/@d4c/numjs)
  instead of NumPy arrays.
- **Command lines**: the argument helpers take the parsers of the [argparse](https://www.npmjs.com/package/argparse)
  package of npm, a port of the Python module.
- **HTTP**: the Orbit client returns the responses of axios instead of the ones of `requests`.
- **BDDF**: the timestamps read from BDDF files are BigInts, in nanoseconds.
